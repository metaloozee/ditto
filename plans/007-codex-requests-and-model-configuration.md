## Outcome and owner

Privileged access performs exact authorized subscription-backed requests. The runtime owns per-conversation model/thinking configuration and effect admission; Pi's default prepared-request semantics determine when a change applies. D1 may project configuration but is not a second authority. No command-wide model pin or model-switch scheduler.

## Integrated interfaces and initial gates

- `apps/web/src/lib/codex-credential-do.ts` owns the product-only credential record, connection authority and serialized renewal. It exposes safe status/freshness results, not tokens, inference or account-capability APIs. Its format-2 encryption authenticates the expected persisted record revision and enforces the complete 60,000-character envelope limit. Preserve revision, crash and disconnect guarantees when adding request operations. Production `fixtureAvailable()` and `renewalAvailable()` remain false.
- `apps/credential-tests/src/entry.ts` supplies the test-only credential subclass; `vitest.config.ts` uses actual Worker/SQLite with synthetic keys and mocked outbound networking. Extend this product seam for credential-bearing fixture requests. Do not move the DO into the runtime or enable the fixture subclass in product composition. Web retains Vitest 4; this isolated suite and runtime use pinned Vitest 3.
- `apps/runtime/src/pi-durable-cooperative-fixture.ts` registers a provider through `createModels().setProvider()` with both `stream` and `streamSimple`, and closes environmental/file authentication discovery. Its optional guard path is synthetic prior art, not an acceptable optional production admission check. The new adapter must require `HostGuard.model()` or the reviewed owning admission boundary on every attempt, including compaction and retry.
- `apps/runtime/src/pi-durable-host.ts` currently associates generation/compaction checkpoints with model, thinking, stream options, transcript digest, task, epoch and attempt before dispatch. It invokes `root.configure({ model }, context)` to initialize `faux-1`. These existing synthetic seams do not prove conversation model-change timing. Before dependent implementation, inspect the pinned Pi 1.0.1 APIs and prove prepared generation and compaction retention across reopen, plus next-prepared-request configuration changes inside an active instruction. Do not patch private schedulers or infer support from a selected-model variable.
- Use explicitly synthetic provider/account identities and a fixed mocked `.invalid` destination for local requests until a supported Ditto live contract is established. Keep synthetic request/stream schemas distinguishable from any future live-provider contract. Fixtures prove validation, admission, response accounting and configuration behavior; they do not prove actual subscription access or account entitlement. Do not copy another application's client identity or combine legacy Codex backend transport with the newer OSS Responses flow by assumption.
- Prepare matching frozen dependencies with lifecycle scripts disabled in a new isolated execution worktree. Main-checkout dependency repair is not authorized by this plan. Stop and report if supported API behavior, bounded request/stream reconstruction or mandatory admission cannot pass its initial local gate.

Stop fixture implementation if bounded reconstruction cannot preserve the selected fixture streaming contract, mandatory fresh admission cannot be enforced for every provider attempt, or pinned Pi APIs cannot preserve prepared configuration.
