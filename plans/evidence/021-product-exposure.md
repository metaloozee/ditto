# 021 product exposure evidence

Executed against `bc10998` in a detached worktree. Nothing staged or committed.

## Routes (all POST, JSON, authenticated by session; user ID never read from the body)

All four share: 401 `{error:"Unauthorized"}` when unauthenticated; 400 `{code:"candidate_admission_ineligible"}` when `PI_DURABLE_PRODUCT_COMMANDS` is unbound; `CandidateCommandError` maps to its `{status, {code}}`; `ContractParseError` (strict parse, unknown or extra fields such as `userId`) maps to 400 `{code}`; any other failure maps to 503 `{code:"runtime_unavailable"}`. Success is 200.

| Route | Request body | 200 response |
|---|---|---|
| `/api/agent/observe` | `{version:1, projectId, sessionId, cursor?}` (strict, parser `parseObservationRequestV1`) | `RuntimeObservationV1`: `{version:1, cursor, snapshot?, events, more}`. A cursor behind or ahead of history gets a fresh `snapshot`. A cursor read has no snapshot. |
| `/api/agent/workspace-action` | `{version:1, kind, projectId, sessionId, message?}` (`parseBrowserWorkspaceActionV1`) | `WorkspaceActionResultV1`. A `denied` result is a 200 body. |
| `/api/agent/models` | `{version:1, projectId, sessionId?}` (`parseCandidateModelsRequestV1`) | `CandidateModelsV1`: `{version:1, status:"available"|"unavailable"|"revoked"|"disconnected", models:[{id, thinking[]}], selection:{model,thinking}|null}` |
| `/api/agent/configure` | not built (Step 5 stopped) | n/a |

Common error codes seen: `runtime_owner_mismatch` (409), `model_unconfigured`, `observation_too_large` (502), `runtime_unavailable` (503).

`models`: credential status other than `connected` gives `disconnected`; missing `codex_fixture_capabilities` row gives `unavailable`; a `revoked` or `unavailable` account snapshot passes through; `selection` is read only when `sessionId` is given, only from committed state (`readSelection`), and is `null` otherwise. `projectId` (and `sessionId` when given) must belong to the user, else `runtime_owner_mismatch`. The credential DO never reports `revoked`, so `revoked` comes only from the account snapshot.

## Fields added

- `ObservationSnapshotV1.health.archive?: {status:"pending"|"blocked"|"complete"}`. Set in `PiDurableHost.observe` from `host_archives.state` (`fenced|retired|final` pending, `blocked`, `complete`; no row absent). Because `observeHistory` and `observe` share that function, archived sessions carry it too. Only in snapshots, not in cursor reads.
- `ObservationSnapshotV1.health.restore?: {checkpointAt:number, effectsUncertain:boolean}`. Set in `CandidateProductCommands.observe` (both active and archived paths) from the latest `candidate_restore_barriers` row with `state='complete'` joined to `runtime_checkpoint_pairs` on `restoredPairId`. `checkpointAt = createdAt` (epoch value as stored), `effectsUncertain = outstandingEffectCount > 0`. No pair ID, digest or object key.
- Contract parsers: `parseObservationRequestV1`, `parseObservationArchiveV1`, `parseObservationRestoreV1` (projection.ts); `CandidateModelsV1`, `parseCandidateModelsV1`, `parseCandidateModelsRequestV1` (configuration.ts).
- `CandidateProductCommandService` now declares `observeOwned`, `workspaceActionOwned`, `deleteProjectOwned`, `modelsOwned`. `configureOwned` is intentionally absent from the interface and the fixture pending a command-less host configuration path (Step 5 stopped); a declared but unimplemented method would fail at runtime over the RPC binding, not at typecheck.
- tRPC `projects.list` and `projects.get` return `hasCandidateSessions: boolean` (any `workspace_sessions` row with `runtimeOwner='pi_durable_v1'`, any status, same user).
- tRPC `projects.deleteProject`: a project with candidate sessions calls `service.deleteProjectOwned(ctx.user.id, id)` and returns `{status:"deleted"|"deleting"}`. With no binding it throws `PRECONDITION_FAILED` "This project has sessions that can't be deleted yet.". A `runtime_owner_mismatch` refusal (mixed project) becomes `PRECONDITION_FAILED` with message `runtime_owner_mismatch`. Other failures become `INTERNAL_SERVER_ERROR` "Failed to delete project.". Legacy-only projects unchanged.
- `apps/web/src/routeTree.gen.ts` regenerated by `pnpm build` (three new routes).

## STOP sub-item: Step 5 (configuration intent)

Stopped as the plan requires. `PiDurableHost.configureOwned` returns `unavailable` unless `dependencies.configuration` is set. For a candidate, that dependency comes only from `candidate.configuration(commandId)` (`pi-durable-product-session.ts` ~266), which calls `product.readCandidateSubject(commandId, ownerVersion)` and binds `authorize` to `product.readCandidateConfigurationAuthority(commandId, ...)`. `configureCandidate(commandId, input)` requires that command to be a stored prompt or follow-up. There is no command-less path. Needed to unblock: a host-side subject and authority source keyed by the session (not a command), plus a `PiDurableProductSession.configure` method. Nothing in the host, session, `configure` route, or fixture was built. 018 must not rely on `/api/agent/configure`.
